# 接口文档0606\-问题澄清

## **1\. 基本信息**



- 服务地址：`http://192.168.1.24:8006`

- 健康检查：`GET /healthz`

- 数据格式：`application/json`

健康检查返回：



```JSON
{
  "ok": true,
  "service": "nlp2teable",
  "version": "3.0.0"
}
```



---



## **2\. 最常用的 3 个接口**



核心只需要这 3 个：



1. `POST /api/chat/submit`

2. `GET /api/chat/result`

3. `POST /api/chat/clarify`

---



## **3\. 推荐调用顺序**



### **3\.1 普通单轮问题**



适用于问题已经足够完整。



调用顺序：



1. `POST /api/chat/submit`

2. 轮询 `GET /api/chat/result?message_id=...`

3. 直到结果不是 `running`

### **3\.2 多轮澄清问题**



适用于第一轮返回 `clarifying`。



调用顺序：



1. `POST /api/chat/submit`

2. 查 `GET /api/chat/result?message_id=...`

3. 如果返回 `clarifying`，调用 `POST /api/chat/clarify`

4. 再查 `GET /api/chat/result?message_id=...`

### **3\.3 第一轮成功后，用户说“结果不对，要重查”**



这种情况 **不要调用** \`/api/chat/clarify\`



正确方式：



1. 继续用原 `conversation_id` 或新建一个 `conversation_id`

2. 重新调用 `POST /api/chat/submit`

3. 把修正后的完整问题重新提交

正确示例：



```JSON
{
  "conversation_id": "conv-001",
  "user_input": "只看AI事业部中项目名称包含804的项目，分析成本情况、主要风险和现金流情况，并生成完整的财务报告"
}
```



---



## **4\. 接口说明**



## **4\.1 提交任务**



- 方法：`POST /api/chat/submit`

请求体：



```JSON
{
  "conversation_id": "conv-001",
  "user_input": "AI事业部的收入怎么样？"
}
```



输入：



- `conversation_id`：可选，会话 ID；建议调用方自己生成并复用

- `user_input`：必填，用户输入的问题

输出：



```JSON
{
  "conversation_id": "conv-001",
  "message_id": "ffbdcbd6-157d-459a-84f3-d430e3fba1ff",
  "task_state": "running"
}
```



- `conversation_id`：本次任务所属会话 ID

- `message_id`：本次任务 ID，后续查询结果时使用

- `task_state`：初始状态，通常为 `running`

建议提取字段：



- `conversation_id`：后续同一会话继续提问时复用

- `message_id`：轮询 `/api/chat/result` 和 `/api/chat/thinking` 时使用

- `task_state`：判断任务是否已进入执行态

---



## **4\.2 ****提交澄清补充**



- 方法：`POST /api/chat/clarify`

- 适用条件：上一轮结果必须是 `clarifying`

请求体：



```JSON
{
  "conversation_id": "conv-001",
  "supplement_text": "开票金额",
  "user_input": "开票金额"
}
```



输入：



- `conversation_id`：必填，和首轮保持一致

- `supplement_text`：必填，本次补充内容

- `user_input`：可选，通常与 `supplement_text` 相同即可

输出：



```JSON
{
  "conversation_id": "conv-001",
  "message_id": "172dc78a-6147-4c65-9ec3-2cc203bac1d8",
  "task_state": "running"
}
```



- `conversation_id`：会话 ID

- `message_id`：本次澄清提交后生成的新任务 ID

- `task_state`：初始状态，通常为 `running`

建议提取字段：



输入侧建议保留：



- `conversation_id`：必须沿用首轮会话 ID

- `supplement_text`：用户本次补充的澄清内容

- `user_input`：如前端保留原输入框内容，可一并记录

输出侧建议提取：



- `conversation_id`：继续关联当前会话

- `message_id`：澄清后新一轮任务 ID

- `task_state`：确认已重新进入执行态

---



## **4\.3 查询任务结果**



- 方法：`GET /api/chat/result`

输入：



- `message_id`：必填，要查询的任务 ID

请求示例：



```HTTP
GET /api/chat/result?message_id=ffbdcbd6-157d-459a-84f3-d430e3fba1ff
```



### **返回一：执行中**



```JSON
{
  "code": 0,
  "conversation_id": "conv-001",
  "message_id": "ffbdcbd6-157d-459a-84f3-d430e3fba1ff",
  "data": {
    "status": "running",
    "task_state": "running",
    "result": null,
    "errorMessage": null
  }
}
```



建议提取字段：



- `conversation_id`：当前任务所属会话

- `message_id`：当前任务 ID

- `data.status`：执行中状态，通常为 `running`

- `data.task_state`：任务阶段状态

- `data.result`：执行中通常为 `null`

- `data.errorMessage`：执行中通常为 `null`

- `data.multi_dimension`：多维分析时可用于展示维度信息

### **返回二：需要澄清**



```JSON
{
  "code": 200,
  "status": "clarifying",
  "task_state": "clarifying",
  "conversation_id": "conv-001",
  "message_id": "ffbdcbd6-157d-459a-84f3-d430e3fba1ff",
  "ai_response": "您提到的收入是指合同额吗？",
  "clarify_question": "您提到的收入是指合同额吗？",
  "interaction": {
    "type": "single_choice",
    "slot_name": "income_definition",
    "problem_type": "income_definition_ambiguity",
    "options": [
      {
        "label": "是",
        "value": "yes_contract_income"
      },
      {
        "label": "否",
        "value": "no_contract_income"
      }
    ],
    "allow_other": true,
    "other_placeholder": "如以上都不符合，请补充更具体的信息"
  }
}
```



输出重点：



- 顶层 `status` / `task_state`：当前需要澄清

- `clarify_question`：需要补充的信息问题

- `interaction.type`：交互类型

- `interaction.options`：可选项列表

- `interaction.allow_other`：是否允许自定义补充

建议提取字段：



- `conversation_id`：继续沿用当前会话

- `message_id`：当前待澄清任务 ID

- `status` 或 `task_state`：识别当前为 `clarifying`

- `ai_response`：可直接展示的澄清提示语

- `clarify_question`：核心追问文案

- `interaction.type`：决定控件类型，如单选、文本补充

- `interaction.slot_name`：澄清槽位标识

- `interaction.problem_type`：澄清问题类别

- `interaction.options[].label`：展示给用户看的选项文案

- `interaction.options[].value`：回传或内部记录用的选项值

- `interaction.allow_other`：是否允许用户自定义输入

- `interaction.other_placeholder`：自定义输入框提示语

- `clarify_context`：保留澄清上下文，便于续问或恢复状态

- `intent`：当前识别出的意图信息

- `multi_dimension.dimension_list`：多维分析涉及的维度清单

- `multi_dimension.primary_dimension`：主维度

- `multi_dimension.secondary_dimensions`：辅维度

### **返回三：执行完成**



```JSON
{
  "code": 0,
  "conversation_id": "conv-001",
  "message_id": "ffbdcbd6-157d-459a-84f3-d430e3fba1ff",
  "data": {
    "status": "success",
    "task_state": "done",
    "queries": [],
    "query_results": [],
    "result": {
      "status": "success",
      "ai_response": "### ① 结论摘要 ...",
      "html_url": "/static/reports/report_xxx.html"
    },
    "errorMessage": null
  }
}
```



输出重点：



- `data.status`：任务最终状态

- `data.queries`：生成的 SQL

- `data.query_results`：SQL 查询结果

- `data.result.ai_response`：Markdown 报告

- `data.result.html_url`：HTML 报告地址

建议提取字段：



顶层建议提取：



- `conversation_id`：当前会话 ID

- `message_id`：当前任务 ID

- `data.status`：最终业务状态

- `data.task_state`：通常为 `done`

- `data.errorMessage`：失败时的错误信息

结果内容建议提取：



- `data.result.ai_response`：主报告正文

- `data.result.html_url`：HTML 报告地址

- `data.result.status`：报告结果状态

- `data.result.default_disclaimers`：默认提示或免责声明

- `data.result.evaluation_summary`：评估摘要

- `data.result.cause_summary`：归因摘要

- `data.result.cause_actions`：建议动作列表

- `data.result.claim_verification`：结论校验信息

- `data.result.data_quality`：数据质量说明

- `data.result.llm_usage`：本次生成报告的模型消耗信息

分析过程建议提取：



- `data.intent`：识别后的意图结构

- `data.multi_dimension.dimension_list`：多维分析维度

- `data.multi_dimension.primary_dimension`：主维度

- `data.multi_dimension.secondary_dimensions`：辅维度

- `data.methodology`：分析方法说明

- `data.queries`：生成的 SQL 列表

- `data.query_results`：每条 SQL 的结果

其中 `data.query_results` 建议重点提取：



- 每条结果的成功/失败状态

- 返回的数据表格或明细数据

- 失败时的错误信息

## **4\.4 查询思考过程**



- 方法：`GET /api/chat/thinking`

- 用途：调试或演示时可用，正式页面不是必需

输入：



- `message_id`：必填，要查询思考过程的任务 ID

请求示例：



```HTTP
GET /api/chat/thinking?message_id=ffbdcbd6-157d-459a-84f3-d430e3fba1ff
```



输出重点：



- `step`：当前执行阶段

- `thinking`：中间分析文本

- `queries`：已生成 SQL

- `query_results`：已回来的部分结果

建议提取字段：



- `conversation_id`：所属会话 ID

- `message_id`：所属任务 ID

- `task_state`：任务阶段状态

- `status`：当前业务状态

- `step`：当前步骤名称

- `current_step`：当前步骤序号

- `total_steps`：总步骤数

- `thinking`：思考过程文本

- `queryPlan`：查询规划

- `intent`：识别意图

- `methodology`：分析方法

- `queries`：已生成 SQL

- `query_results`：中间查询结果

- `llm_usage`：模型调用消耗

- `interaction`：若进入澄清，保留交互信息

- `multi_dimension`：多维分析维度信息

- `error`：失败时错误信息

说明：



- `/api/chat/thinking` 和 `/api/chat/result` 不是两个独立任务，也不是两条并行执行链路

- 它们都是读取同一个 `message_id` 对应的任务状态

- `/api/chat/thinking` 侧重返回中间过程，如 `thinking`、`step`、`queries`、`query_results`

- `/api/chat/result` 侧重返回最终结果，如 `data.result.ai_response`、`data.result.html_url`

- 可以并行轮询这两个接口，但底层任务只有一个

- 实际执行顺序是：任务启动后持续写入思考过程，最后在任务完成时写入最终结果

- 因此可理解为“同一任务的过程信息和结果信息同时可读”，但不是“两套逻辑并行各跑一遍”

推荐使用方式：



- 普通业务页面：主要调用 `/api/chat/result`

- 需要展示推理过程、SQL 过程、阶段进度时：额外调用 `/api/chat/thinking`

- 若前端想做实时过程展示，可轮询 `/api/chat/thinking`，同时继续轮询 `/api/chat/result` 判断是否结束

---





## **5\. 状态说明**



主要状态：



- `running`：执行中，继续轮询

- `clarifying`：需要用户补充信息

- `success`：执行成功

- `partial_success`：部分成功，部分查询失败

- `no_data`：查到了，但没有数据

- `sql_failed`：SQL 失败

- `error`：系统错误

查询结果时的结束条件：



- 返回顶层 `status = clarifying`

- 或 `data.status` 为以下任意一种：`success`、`partial_success`、`no_data`、`sql_failed`、`error`、`aborted`

建议轮询频率：



- 每 `1~2` 秒一次

---



## **6\. 常见坑**



### **6\.1 第一轮已经成功，不要再调\`/clarify\`**



错误做法：



- 第一轮已经出报告

- 用户说“筛选错了，改成 AI事业部、项目名包含804”

- 前端继续调用 `/api/chat/clarify`

结果：



- 系统可能把补充内容当成一个新问题

- 原来的完整财务报告意图可能丢失

正确做法：



- 重新调用 `/api/chat/submit`

- 把修正后的完整问题重新提交

### **6\.2\`message\_id\` 和 \`conversation\_id\` 不要混用**



- `message_id`：用于查某一次任务结果

- `conversation_id`：用于串起同一轮会话

### **6\.3 服务重启后，旧\`message\_id\` 可能失效**



- `result / thinking / abort` 查不到时，优先确认是不是服务刚重启过

## **7\. 历史接口**



如需查询会话列表和历史详情，还可以使用：



- `GET /api/history/conversations`：查询会话列表

- `GET /api/history/detail?conversation_id=...`：查询会话详情

- `DELETE /api/history/conversation/{conversation_id}`：删除指定会话

这部分不是首版必需，可按需要接入。



### **7\.1 会话列表\`/api/history/conversations\`**



输入：



- `limit`：可选，返回条数

- `offset`：可选，分页偏移

输出：



- `items`：会话列表

- `total`：本次返回数量

建议提取字段：



- `items[].conversation_id`：会话 ID

- `items[].title`：会话标题

- `items[].updated_at`：最近更新时间

- `items[].created_at`：会话创建时间

- `items[].user_id`：用户 ID，若前端不需要可不展示

- `total`：列表总数或当前页数量

其中最常用字段：



- `title`

- `updated_at`

- `conversation_id`

### **7\.2 会话详情\`/api/history/detail\`**



输入：



- `conversation_id`：必填，会话 ID

输出：



- `conversation_id`：会话 ID

- `title`：会话标题

- `turns`：该会话下的历史轮次

建议提取字段：



会话级建议提取：



- `conversation_id`

- `title`

单条历史记录 `turns[]` 建议提取：



- `id`：该轮记录 ID

- `turn_number`：轮次序号

- `user_input`：用户原始问题

- `ai_thinking`：模型思考过程

- `ai_response`：最终回复内容

- `html_url`：HTML 报告地址

- `status`：该轮任务状态

- `created_at`：该轮创建时间

其中最常用字段：



- `user_input`

- `ai_thinking`

- `ai_response`

- `html_url`

- `created_at`

### **7\.3 删除会话\`/api/history/conversation/\{conversation\_id\}\`**



输入：



- `conversation_id`：必填，要删除的会话 ID

输出：



- `success`：是否删除成功

- `message`：删除结果说明

---



## **8\. 结论**



记住两点即可：



1. 正常链路：`submit -> result -> clarify(如需要) -> result`

2\. 成功后的纠偏重跑：**\*\*重新走 \`submit\`，不要走 \`clarify\`\*\***
